Manual accessibility tests for visually hidden CSS

  • Overview
  • Implementation breakdown
  • Manual test page

Testing rule: do not assume the proposed version passes because it is labelled "proposed." Record what the assistive technology actually announces and what is visually observable. Some tests are expected to show GOV.UK and the proposed version behaving the same.

Test environment

Recommended assistive-technology coverage

  • NVDA with Firefox, Chrome, and Edge on Windows.
  • JAWS with Chrome and Edge on Windows.
  • VoiceOver with Safari on macOS, including heading navigation.
  • VoiceOver with Safari on iOS.
  • TalkBack with Chrome on Android.
  • Keyboard only at 100%, 200%, and 400% browser zoom.
  • Windows Magnifier and macOS Zoom while moving keyboard focus.
  • Forced-colours or high-contrast mode where available.

Test 8: 400% zoom and magnification

Purpose: verify that revealing focusable content does not retain one-pixel dimensions, clipping, hidden overflow, or white-space: nowrap. At a 1280 CSS pixel starting viewport, 400% zoom corresponds to the 320 CSS pixel width used by WCAG 2.2 Reflow.

  1. Set browser zoom to 400%.
  2. Use Tab to move through the three skip-link samples in Test 6.
  3. Confirm the focused link is visible without horizontal scrolling caused by the link itself.
  4. Repeat with Windows Magnifier or macOS Zoom if available.

Why the proposed state model matters: when the proposed focusable element is revealed, the hiding selector no longer matches at all. This means future hidden-state properties do not need a matching "undo" declaration. This is primarily a maintainability and regression-resistance advantage; the current Drupal implementation may still pass this test today.

Test 9: generated-space regression checks

Purpose: make sure the screen-reader fix does not create worse announcements elsewhere.

  • Navigate the GOV.UK and proposed samples by headings with macOS VoiceOver/Safari and record whether "space" is announced.
  • Check iOS VoiceOver to see whether hidden text becomes a separate announcement.
  • Check punctuation such as Save draft:, parentheses, and RTL text in an expanded test if problems appear.
  • Check that generated content is not exposed as an extra stop or element in browse navigation.
