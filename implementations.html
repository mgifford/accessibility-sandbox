Implementation breakdown: visually hidden CSS

  • Overview
  • Implementation breakdown
  • Manual test page

This page separates the three implementations idea by idea. The explanations focus on what each declaration does, why it exists, and what it means for blind screen-reader users, users of magnification or high zoom, and keyboard-only users.

1. Existing Drupal 11.x implementation

Source: Drupal API: hidden.module.css, 11.x.

.visually-hidden {
  position: absolute !important;
  overflow: hidden;
  clip: rect(1px, 1px, 1px, 1px);
  width: 1px;
  height: 1px;
  word-wrap: normal;
}

.visually-hidden.focusable:active,
.visually-hidden.focusable:focus-within {
  position: static !important;
  overflow: visible;
  clip: auto;
  width: auto;
  height: auto;
}

Line-by-line explanation

position: absolute !important;
Removes the element from normal document flow so its one-pixel box does not create visible layout space. This is effective for hiding, but absolute positioning is also implicated in the loss of surrounding whitespace in some browser and accessibility API combinations. The !important protects the utility from accidental component-level overrides.
overflow: hidden;
Prevents text from painting outside the tiny one-pixel box. Without clipping or overflow control, hidden text can become visually exposed.
clip: rect(1px, 1px, 1px, 1px);
Clips the absolutely positioned box to an effectively invisible rectangle. This is the legacy CSS clip technique. The property is deprecated and modern guidance uses clip-path instead.
width: 1px; and height: 1px;
Shrink the element to a tiny box. These declarations are part of the conventional visually-hidden pattern. Because Drupal does not also reset margin, padding, and border here, inherited or component styles can theoretically enlarge the effective box.
word-wrap: normal;
Restores the older wrapping behavior if another rule set word-wrap or overflow-wrap. It does not prevent normal word wrapping inside the one-pixel box. GOV.UK instead uses white-space: nowrap so long hidden text is not laid out one word per line while hidden.
.visually-hidden.focusable:active, .visually-hidden.focusable:focus-within
This is an important Drupal behavior. It reveals a hidden element when it is active or when it or any descendant contains focus. The use of :focus-within supports containers, not just directly focusable elements.
position: static !important;
Returns the revealed element to normal flow. For keyboard and magnification users this makes the previously hidden content occupy ordinary page space.
overflow: visible; clip: auto; width: auto; height: auto;
Individually undo the main hiding declarations. This works with the current small rule set, but it creates a maintenance problem: every new property added to the hidden state may need a corresponding reset in the visible state.

Main accessibility strengths

  • Uses a long-established visually-hidden technique.
  • Preserves :focus-within, which is useful when a hidden wrapper contains a keyboard-focusable descendant.
  • Revealed content returns to normal document flow.

Main limitations

  • No generated whitespace fix for the NVDA and JAWS concatenation problem described in Drupal issue #3591112.
  • Uses deprecated clip.
  • Uses a reset block for the focusable state, so the reset list must remain synchronized with the hiding list.
  • Does not normalize margin, padding, or border while hidden.

2. GOV.UK Frontend implementation

Source: GOV.UK Frontend _visually-hidden.scss. GOV.UK authors this as Sass mixins. The CSS below expresses the relevant behavior in plain CSS for comparison.

.govuk-visually-hidden {
  position: absolute !important;
  width: 1px !important;
  height: 1px !important;
  margin: 0 !important;
  padding: 0 !important;
  overflow: hidden !important;
  clip: rect(0 0 0 0) !important;
  clip-path: inset(50%) !important;
  border: 0 !important;
  white-space: nowrap !important;
  user-select: none;
}

.govuk-visually-hidden::before {
  content: "\00a0";
}

.govuk-visually-hidden::after {
  content: "\00a0";
}

.govuk-visually-hidden-focusable:not(:active):not(:focus) {
  /* same hiding declarations */
}

Line-by-line explanation

position: absolute !important;
Removes the hidden box from normal layout. GOV.UK documents the trade-off that negative margins can affect VoiceOver order, so it explicitly uses a zero margin rather than the negative-margin variant found in some visually-hidden recipes.
width: 1px !important; height: 1px !important;
Constrains the hidden box to one pixel in each dimension.
margin: 0 !important; padding: 0 !important; border: 0 !important;
Neutralizes box-model styles that could otherwise make an arbitrary component larger than the intended one-pixel hiding box. This makes the utility more predictable when applied to different elements.
overflow: hidden !important;
Prevents hidden text from visually escaping the small box.
clip: rect(0 0 0 0) !important;
Legacy fallback retained by GOV.UK for Internet Explorer 11. GOV.UK's own source comment says that IE11 support is the reason it remains.
clip-path: inset(50%) !important;
Modern clipping mechanism. The inset clips the painted content away while the content remains in the accessibility tree. MDN lists clip-path as widely available.
white-space: nowrap !important;
Stops long hidden content from wrapping one word per line in a one-pixel box. This addresses a known class of screen-reader problems associated with "smushed" off-screen text.
user-select: none;
Prevents hidden text from being accidentally selected or copied. GOV.UK explicitly documents this as a copying/usability choice, not as part of the screen-reader hiding mechanism. Drupal does not need to inherit this policy automatically.
::before and ::after with content: "\00a0";
Insert a non-breaking space before and after non-focusable visually hidden text. GOV.UK added this because absolute positioning can cause surrounding whitespace to disappear from the accessibility tree, producing announcements such as words being concatenated. Their PR #3836 reports testing across JAWS, NVDA, VoiceOver, and TalkBack. A known caveat is that macOS VoiceOver in Safari can explicitly announce the inserted space during heading navigation.
.govuk-visually-hidden-focusable:not(:active):not(:focus)
GOV.UK does not hide the focusable helper first and then reset it. Instead, the hiding declarations apply only while the element is neither active nor focused. When the element receives focus, the hiding declarations stop matching and the element's ordinary CSS applies. This is a cleaner state model for a directly focusable element such as a skip link.

Important GOV.UK-specific details

  • Its source includes an additional escaped .\:focus companion selector for a PostCSS pseudo-class plugin. The standalone test site does not use that plugin, so the test CSS omits that build-tool-specific selector.
  • The focusable helper is documented for a focusable element such as a link. It does not attempt to reproduce Drupal's broader :focus-within wrapper behavior.

3. Proposed Drupal adaptation

.visually-hidden:not(.focusable),
.visually-hidden.focusable:not(:active):not(:focus-within) {
  position: absolute !important;
  width: 1px !important;
  height: 1px !important;
  margin: 0 !important;
  padding: 0 !important;
  overflow: hidden !important;
  clip-path: inset(50%) !important;
  border: 0 !important;
  white-space: nowrap !important;
}

.visually-hidden:not(.focusable)::before,
.visually-hidden:not(.focusable)::after {
  content: "\00a0";
}

Selector logic first

.visually-hidden:not(.focusable)
Ordinary visually hidden content is always hidden visually and remains available to accessibility APIs. This is where the generated whitespace fix applies.
.visually-hidden.focusable:not(:active):not(:focus-within)
A focusable Drupal visually-hidden element is hidden only when it is not active and neither it nor a descendant contains focus. As soon as focus enters it, this selector stops matching. There is no focused-state reset block to maintain.

Declaration-by-declaration explanation

position: absolute !important;
Keeps hidden content out of normal layout while hidden. This is retained because removing absolute positioning would change layout behavior and requires a substantially larger regression test effort.
width: 1px !important; height: 1px !important;
Creates the conventional tiny hiding box.
margin: 0 !important; padding: 0 !important; border: 0 !important;
Prevents arbitrary component styling from enlarging the hidden box. Unlike a permanent reset, these declarations disappear automatically for the .focusable variant when it is revealed.
overflow: hidden !important;
Prevents hidden content from visually escaping the box.
clip-path: inset(50%) !important;
Uses the modern clipping mechanism. The deprecated clip fallback is intentionally omitted because Drupal does not support Internet Explorer 11.
white-space: nowrap !important;
Prevents hidden text from wrapping into many one-word lines. For .focusable content, this declaration stops applying when focus enters, so the revealed control can wrap according to its normal theme or component CSS at high zoom.
::before and ::after with content: "\00a0";
Adopts GOV.UK's authored non-breaking-space fix for non-focusable visually hidden content. It is excluded from the focusable variant because the focusable helper has different interaction semantics and GOV.UK does not apply the generated-space rule to its focusable helper.

Why this is different from copying GOV.UK

  • No legacy clip: Drupal does not need GOV.UK's IE11 fallback.
  • No user-select: none: Drupal should not globally disable selection as part of an accessibility utility unless it has a Drupal-specific requirement to do so.
  • Preserves :focus-within: this maintains existing Drupal behavior for wrappers containing a focusable descendant.
  • Preserves Drupal's two-class API: existing markup uses class="visually-hidden focusable", so the proposal changes the state model without requiring new markup.

Side-by-side summary
