This site compares three approaches to visually hiding content while retaining it in the accessibility tree: Drupal 11.x core, GOV.UK Frontend, and a proposed Drupal adaptation for issue #3591112.

Purpose: this is a test and documentation site, not production CSS. The proposed implementation should not be committed to Drupal core until the manual assistive-technology testing described on the test page is complete.

What is being tested

  • Whether visible and visually hidden text retain a word boundary in NVDA, JAWS, VoiceOver, and TalkBack.
  • Whether focusable hidden content becomes fully visible and usable with a keyboard.
  • Whether Drupal's existing :focus-within behavior continues to reveal a wrapper when focus moves to a descendant.
  • Whether revealed content wraps normally at 200% and 400% browser zoom.
  • Whether headings, buttons, legends, summaries, paragraphs, and table cells produce unexpected screen-reader announcements.

What the proposed version changes

  • Replaces deprecated clip with clip-path: inset(50%).
  • Adds generated non-breaking spaces around non-focusable visually hidden content to preserve text boundaries in affected accessibility APIs.
  • Uses white-space: nowrap while content is hidden.
  • Hides .visually-hidden.focusable only while it is not active and does not contain focus, instead of hiding first and undoing selected properties later.
  • Preserves Drupal's :focus-within behavior.
  • Does not copy GOV.UK's user-select: none because text-selection policy is separate from the hiding mechanism.

Important comparison caveat

The proposed Drupal version should not be described as generally better than GOV.UK Frontend. GOV.UK has broader published assistive-technology testing. The Drupal proposal adapts that work to Drupal's existing API and browser-support requirements. In particular, the :focus-within test demonstrates a Drupal compatibility requirement, not a defect in the documented GOV.UK usage pattern.
